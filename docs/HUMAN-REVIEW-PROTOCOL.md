# بروتوكول المراجعة البشرية

هذا البروتوكول يصف متى يجب أن يتوقف النظام عن اتخاذ قرار آلي ومتى يراجع الفريق الناتج. لا تُسجّل أسماء أو محادثات حقيقية في المستودع.

## متى نطلب مراجعة بشرية؟

- عند ظهور `explicit-contradiction` في المواد المسترجعة.
- عند وجود ادعاءات `partial` أو `conflicting` لا تكفي لإجابة موثقة كاملة.
- عند فشل verifier أو evidence gate.
- عند إضافة مصدر جديد إلى corpus.

## ماذا يراجع الخبير؟

1. صحة هوية المصدر والموضع.
2. هل النص الحرفي أو `curated-summary` وُسِم بصورة صحيحة؟
3. هل الادعاء يطابق الدليل أم يتجاوز معناه؟
4. هل الامتناع مناسب عند نقص المرجع؟
5. هل يوجد اختلاف بين مصدرين يحتاج صياغة تحفظية؟

## قاعدة عدم التحكيم الآلي

رصد التعارض لا يعني اختيار «المصدر الصحيح». واجهة المنتج تعرض التباين وتربطه بالمقاطع، ثم تترك الحكم للباحث/المراجع المختص.

## سجل النتيجة

في نسخة الفريق الداخلية، يسجّل المراجع فقط نتيجة مجمعة مثل: `pass`, `needs-fix`, `remove-claim`. لا تُرفع أي بيانات شخصية إلى GitHub.
