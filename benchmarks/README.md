# Benchmark — Rafiq Al-Qulub

The benchmark is deliberately kept outside `tests/` so the public repository contains a reproducible evaluation suite without exposing private traces or production session data.

## Run

1. Start the app: `npm run dev`.
2. In another terminal run: `npm run benchmark`.
3. Optional: `node benchmarks/run-benchmark.mjs --url http://localhost:3000 --limit 10`.

The runner sends the same fixed questions through:

- `mode=baseline`: lexical + topic baseline.
- `mode=ai`: planner + embeddings + hybrid retrieval + AI re-ranking + evidence gate + claim verification.

It writes an aggregate report to `benchmarks/results/latest.json` (git-ignored so teams do not accidentally publish changing local result snapshots).

## Metrics

- Retrieval source recall / hit: how much of the expected source set was retrieved, and whether at least one expected source appears.
- Retrieval chunk recall / hit: for cases with `expectedChunks`, how much of the gold passage set was retrieved.
- Topic hit: at least one returned topic matches the expected topic set.
- Outcome accuracy: response outcome matches the benchmark expectation.
- Citation grounding: verified claims cite returned passages; when expected sources are supplied, the cited passages are also checked against the expected source set.
- Abstention accuracy: out-of-scope / unsupported prompts are refused rather than generated.
- AI activation: eligible in-scope cases complete the evidence-gated AI pipeline.

Numbers are generated by the runner. Do not hand-edit them into documentation.
